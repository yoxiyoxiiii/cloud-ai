## 1. 域语义（perms 下发域特有）

- **permissions 语义**：该会话的**登录时权限快照**——登录（或 refresh）时聚合的 sys_menu.perms 全集（经 用户→角色(启用)→角色菜单绑定→菜单），写入 Redis `sso:online:{jti}` 的 OnlineSession；网关每次请求读同一键注入 X-User-Perms 供服务层 @PreAuthorize 执法。**本端点读同一键**——前端按钮显隐与后端执法**同源同值**（快照时效语义见 menu-nav §3：权限变更需重登/refresh 生效，不实时）
- **会话内不变性**：快照在会话生命周期内不变（MVP 无静默刷新；token 过期/强退/注销 → 网关 401 → 前端清态重登）——前端可在整个 SPA 会话内缓存本次响应，无需轮询
- **匹配语义**：permissions 为精确字符串集合（`<svc>:<entity>:<action>`），**无通配符**（对齐 @PreAuthorize hasAuthority 精确匹配）；前端指令匹配规则见 §4

## 2. 新端点：当前会话权限快照 `GET /sso/auth/me`

- 权限：**仅认证（无 @PreAuthorize）**——网关验 token（无/坏/过期 token 为真实 HTTP 401 + R body，通用例外）；任何已登录用户可访问，返回**该会话自己的**快照投影，无越权面（与 user-nav"仅认证"同构：me = 会话视角投影，/auth/online = 管理视角全量需 `sso:online:list`）
- 入参：无 body；header 必带 `Authorization: Bearer <accessToken>`（网关对非白名单路由强制；与 logout 同款由服务端 `@RequestHeader` 接收）
- 行为：
  1. accessToken 解 JWT 取 jti（tokenId）——sso 既有范式（logout 同款）
  2. 读 Redis `sso:online:{jti}` 的 OnlineSession JSON——与网关执法读取同一键
  3. 转 CurrentUserVo（account + permissions 两字段，最小暴露：不含 userId/ip/loginTime/tokenId）
- 返回 `R<CurrentUserVo>`——字段表：

| 字段 | 类型 | 必返 | 说明 | 示例 |
|---|---|---|---|---|
| account | string | 是 | 会话登录账号（与 token 声明一致，e2e 身份绑定断言用） | `"admin"` |
| permissions | string[] | 是 | 该会话权限快照全集；零角色/零绑定用户为 `[]`（合法态，按钮全隐）；顺序不承诺（前端集合语义消费） | `["system:role:list", "system:role:edit"]` |

admin 种子数据下的返回示例（节选，全量 17 项 perms：user 域 6 + role 域 5 + menu 域 4 + sso 域 2；M 目录 10/20 perms 为空串不入集合）：

```json
{ "code": 200, "msg": "操作成功", "data": {
  "account": "admin",
  "permissions": ["system:user:list", "system:user:add", "system:user:edit", "system:user:remove", "system:user:resetPwd", "system:user:assignRole", "system:role:list", "system:role:add", "..."] } }
```

N2 场景受限用户（绑 F 122 角色修改 + 半选父 10/12）示例：

```json
{ "code": 200, "msg": "操作成功", "data": { "account": "e2enavXXXX", "permissions": ["system:role:list", "system:role:edit"] } }
```

- 错误码：

| code | 含义 | 出现路径 |
|---|---|---|
| 200 | 成功（含空 permissions `[]`） | 正常路径 |
| 401 | 未认证 | **网关**：无/坏/过期 token、已注销、已被强退（HTTP 真实 401 + R body，通用例外）；**防御路径**（理论不达）：网关刚放行而 Redis 会话竞态缺失 / JWT 解析异常 → HTTP 200 + body 401，msg `"会话已失效，请重新登录"` |
| 403 | **不出现**（无 @PreAuthorize） | — |

- **错误码占位声明**：本轮**零新增**业务错误码（2xxx/3xxx 段零占用；401 为既有通用码复用，satisfies 前端 request.ts 既有 body 401 → 清态跳登录分流，无需新分支）。3xxx 段 3008 起仍整体预留给 backlog「内置角色/菜单保护」另案（沿用 menu-nav §4 声明）
- 前端消费：**是**（`api/auth.ts getMe()` → `stores/perm.ts`，见 §4）

## 4. 前端消费映射与指令语义（v-perms 定稿口径）

| 项 | 约定 |
|---|---|
| 端点消费方 | `api/auth.ts getMe()` → `stores/perm.ts ensureLoaded()`——**守卫内与 user-nav 并行原子加载**（任一失败走既有失败矩阵：401→login / 其余→MenuError）；组件挂载先于完成（守卫 `return to.fullPath` 重匹配保证） |
| 指令名 | `v-perms`，全局注册（main.ts） |
| 值类型 | `string \| string[]`：单值=快照含该 perms 显示；**数组=任一命中（some）显示** |
| 隐藏语义 | **DOM 移除**（v-if 语义，非 disabled）——"可见≈可操作"，disabled 暴露功能存在性且留间距残迹 |
| 未加载态 | fail-closed：store 未 loaded 恒判无权限（保守隐藏，与执法同向；守卫原子门下理论不可达，纯防御） |
| 非法值（undefined/空串/空数组） | 判无权限隐藏，不抛错 |
| TypeScript | `CurrentUserVo { account: string; permissions: string[] }`（types/api.ts 增补）；`hasPerm(value?: string \| string[]): boolean` 便利函数导出（供 v-if/列级条件复用） |
| F5 / 登出 / 重登 | F5 守卫重拉；登录页 onMounted 三件套 reset（tags/menu/perm）——重登账号按钮集无残留 |

## 5. menu-nav §3 时效语义增补（按钮层收窄）

menu-nav §3 建立的两维分离（导航可见性实时 / 操作权限登录快照）**结论不变**，本节收窄其第 1 条中间态的按钮层表述：

- **原文**（menu-nav §3 第 1 条）："菜单可见但操作被拒"——绑定了菜单但 perms 快照未含对应操作权限 → 页面可进，**按钮点击得 HTTP 200 + body 403 toast**
- **收窄后**：页面可进，**按钮已随快照隐藏**（v-perms，显隐=快照）；该中间态的可见残余仅为"操作列空壳"。body 403 仍会出现于：① 快照滞后窗口（权限变更后未重登，旧快照仍含已回收的 perms——按钮显但执法拒）；② 绕过 UI 直连 API。**服务层 403 恒为最终防线**（e2e N5 直连断言固化）
- **e2e 纪律增补**（接 menu-nav §3 末条）：**可以断言**"按钮随登录时快照显隐"（绑定先于登录的两维同设场景，如 N2f）；**不可断言**"改完角色绑定刷新即改按钮显隐"（操作权限是快照，须重登/refresh）——与导航域"改完绑定刷新即可见"形成两维对照
- menu-nav §3 第 2 条中间态（"菜单不可见但快照权限仍在"）不变

## 6. 挂载面基线（本轮 12 挂载点，契约对齐用）

对照种子 SQL（111-133）；后端零配合改动，仅前端模板挂指令：

| 页面 | 按钮 → perms |
|---|---|
| /system/user | 新增用户→`system:user:add`；编辑→`system:user:edit`；重置密码→`system:user:resetPwd`；分配角色→`system:user:assignRole`；删除→`system:user:remove` |
| /system/role | 新增角色→`system:role:add`；编辑→`system:role:edit`；分配权限→`system:role:assignMenu`；删除→`system:role:remove` |
| /system/menu | 新增菜单→`system:menu:add`；编辑→`system:menu:edit`；删除→`system:menu:remove` |

页面级访问（C 节点 list perms）不挂指令（由动态路由/导航管）；弹窗内部不挂（入口按钮已收口）。
