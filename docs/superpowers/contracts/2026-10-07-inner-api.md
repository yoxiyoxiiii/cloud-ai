# 服务间内部接口 API 契约（/inner/**，cloud-system）

- 日期：2026-10-07
- 状态：**inner 域现行版（v1）**——由架构-agent 定稿，配合翻译 Provider 远程化需求（设计 `docs/superpowers/specs/2026-10-07-translate-remote-builtin-protection-design.md`）
- **域性质（先读）**：本域是**后端服务间内部契约**（Feign 调用专用），**不是前端对齐物**——前端不得调用任何 /inner/** 端点；网关对 `/{service}/inner/**` 一律 403 是**设计行为**（inner-block 规则，phase3 落地）。通用约定（R 结构 / Long→String / Jackson 格式）沿用 pilot §1
- **与既有契约的关系**：本域为新建；既有 `GET /inner/user/{account}`（phase3 登录链路实现，当时散见于 phase23 设计/计划文档，无契约本体）由本文档**声明性收编**（§2.1）——原实现与语义零变化，仅补契约记录。本轮新增 §2.2/§3.1 两端点（翻译远程回源数据源）
- 约定：发现文档与实测不符，回报主控修订契约，不自行猜测

## 0. 变更点清单（相对既有契约）

| # | 对象 | 变更 | 性质 |
|---|---|---|---|
| 1 | inner 域 | 新建本契约文档；收编 /inner/user/{account} | 新域 + 声明性收编（原端点零变化） |
| 2 | cloud-system | 新增 `GET /inner/user/all`（§2.2）、`GET /inner/dict/items/{dictKey}`（§3.1）——翻译远程回源数据源 | additive 新端点（服务间） |
| 3 | 网关 | **零改动**——`/system/inner/**` 屏蔽规则（403）已有，新端点天然被保护 | 无 |

## 1. 域语义（inner 域特有）

- **调用方**：仅集群内服务经 Feign（服务名寻址 + loadbalancer）；本轮消费方为 `cloud-common-translate-remote-starter`（程序式 Feign 客户端），未来 bpmn 等服务引该模块即获得本域能力
- **鉴权**：无 @PreAuthorize、无 JWT——内网信任边界内（集群内网不可达性 + 网关屏蔽双保障）；**不经过网关**（网关 403），直连服务端口或服务名负载均衡
- **返回结构**：R\<T\> 同全局（HTTP 恒 200 + body.code；服务内部异常按 GlobalExceptionHandler 通用码）
- **数据时效**：inner 端点**直读 DB，不经 Redis 缓存**（缓存消费发生在调用方：远程 Provider 拿到数据后由调用方的 TranslationCacheService 写 trans:* 键）——两端点读到的是实时数据
- **降级责任在调用方**：本域端点失败（超时/非 200）由调用方 Provider 转异常、缓存层降级为空译文（设计 §6）——本域自身不设 fallback 语义

## 2. 用户内部端点（/inner/user，cloud-system）

### 2.1 按账号取登录聚合 `GET /inner/user/{account}`（既有收编，零变化）

- 实现：`InnerUserController`（phase3）；供 sso 登录链路（SystemUserClient）调用
- 入参（path）：`account` string（显式命名 `@PathVariable("account")`）
- 返回 `R<LoginUserDTO>`——账号不存在返回 `data=null`（**不报错**——登录失败语义由 sso 侧判定）
- 错误码：无业务码（404 语义以 data=null 表达）
- 消费客户端：cloud-system-api `SystemUserClient#getUserByAccount`（2026-10-09 统一声明归位；sso 经 fallbackFactory 等价降级 2002）

### 2.2 全量用户投影 `GET /inner/user/all`（本轮新增）

- 用途：翻译回源（account/id → nickname）；实现于 `InnerUserController` 追加（与 §2.1 `/{account}` 共存——精确路径优先于模板匹配）
- 入参：无
- 行为：全量未删除用户投影（**含停用用户**——审计字段翻译需要所有用户的昵称，停用不等于名字消失）；委托既有 `UserSourceProvider`（同一数据源 as 翻译本地回源）
- 返回 `R<List<UserEntry>>`——空库返回 `data=[]`（非 null）

| 字段 | 类型 | 必返 | 说明 | 示例 |
|---|---|---|---|---|
| id | string | 是 | 用户 ID（Long→String 全局序列化；消费端 Jackson coercion 反序列化回数值） | `"1"` |
| account | string | 是 | 登录账号 | `"admin"` |
| nickname | string | 是 | 昵称 | `"管理员"` |

```json
{ "code": 200, "msg": "操作成功", "data": [
  { "id": "1", "account": "admin", "nickname": "管理员" } ] }
```

- 错误码：无业务码（恒 200 + 数组，含空数组）
- 量级语义：全量单键口径（设计 D5/上轮 §4.1）——企业内部用户量级几百~几千；数万以上时消费方缓存模型需演进（上轮移交备忘 6，两端点形状不变）
- 消费客户端：cloud-system-api `SystemUserClient#listAll`（bpmn 审批人校验，降级 1002）；translate-remote-starter 程序式 SystemTranslateClient 为记档特例（设计 D8）

## 3. 字典内部端点（/inner/dict，cloud-system）

### 3.1 按字典键取启用项 `GET /inner/dict/items/{dictKey}`（本轮新增）

- 用途：翻译回源（dictKey → 启用项列表）；实现于新建 `InnerDictController`（controller/feign/ 包）；委托既有 `DictItemSourceProvider`
- 入参（path）：`dictKey` string（显式命名 `@PathVariable("dictKey")`）
- 行为：按**消费口径**返回——类型 status=0 且 deleted=0 ∧ 项 status=0 且 deleted=0，`ORDER BY sort ASC, id ASC`（与管理端消费端点 `/system/dict/data/type/{dictKey}` 完全同源同口径）
- **dictKey 不存在 / 类型停用 / 无启用项：一律 `200 + 空数组`**（与消费端点空数组语义一致；空数组是合法缓存数据，调用方会正常写缓存 TTL）
- 返回 `R<List<DictItemEntry>>`

| 字段 | 类型 | 必返 | 说明 | 示例 |
|---|---|---|---|---|
| value | string | 是 | 存库值 | `"0"` |
| label | string | 是 | 展示标签 | `"正常"` |
| sort | number | 是 | 排序号 | `1` |

- 错误码：无业务码

## 4. 消费方与验证口径

| 端点 | 消费方 | 验证 |
|---|---|---|
| /inner/user/{account} | sso（引 cloud-system-api `SystemUserClient`，2026-10-09 归位） | 既有链路回归 |
| /inner/user/all | bpmn（cloud-system-api `SystemUserClient#listAll`）+ translate-remote-starter RemoteUserSourceProvider（程序式，记档特例） | curl 直连 9202；网关 18080 得 403 为设计行为实证（B7） |
| /inner/dict/items/{dictKey} | translate-remote-starter RemoteDictSourceProvider | 同上 |

- **消费客户端归位（2026-10-09）**：/inner/user 两端点的声明式消费统一走 cloud-system-api `SystemUserClient`（fallbackFactory 等价降级：getUserByAccount→2002、listAll→1002）；translate-remote-starter 程序式 client 维持原状（设计 D8 豁免）。

- **真实跨服务 Feign 链路验证推迟至 bpmn 阶段 4 接入**（本轮无第二消费者，记档设计 §9.1）——本轮以单测（mock client）+ 直连 curl 覆盖

## 5. 宽松语义清单

1. **内网信任**：inner 端点无认证——安全性依赖"网关屏蔽 + 集群内网不可达"，新增 inner 端点必须确认目标服务已有网关屏蔽规则（本域两端点落在既有 /system/inner/** 规则内）
2. **数据实时无缓存**：两端点直读 DB；调用方缓存（trans:*，TTL 30min + 写操作 DEL）承担一致性——极端路径译文陈旧窗口见 translation-api §5.2
3. **user/all 含停用用户**：口径=deleted=0（不含 status 过滤）——与 trans:user 缓存键口径一致
4. **空数组多因一果**：dict/items 空 = 未知 dictKey / 类型停用 / 无启用项，调用方不区分（与消费端点空数组语义同源）

## 6. 错误码声明

本域**零新增错误码**：空态以 200 + data=null（用户单查）/ 空数组（列表）表达；服务异常走 GlobalExceptionHandler 通用码；调用方对非 200 一律按回源失败降级（不透传错误给业务响应）。3xxx 账本现状与接续见 `2026-10-07-builtin-protection-api.md` §4（3013-3017 占用、3018+ 预留 bpmn）。
