## 1. 通用

- 网关前缀 `/ai`（StripPrefix=1 → 服务 `/rag/kb`...）；本地直连 :8010 须手工带 header。
- 鉴权（四权限拆分）：**列表/文件查询与菜单 182 用 `ai:kb:list`**；**创建与上传（§2/§3）用
  `ai:kb:add`**（按钮种子 183）；**编辑（§5）用 `ai:kb:update`**（按钮种子 184）；**删除（§6）用
  `ai:kb:delete`**（按钮种子 185）。
- 错误码：403 无操作权限 / 1001 参数校验 / 500 系统异常（全局兜底，msg「系统异常，请稍后重试」）/
  5003 知识库名称已存在（创建与编辑共用——编辑改名为他库现有名同此码）/ 5004 知识库不存在（上传、
  文件查询、编辑、删除目标不存在共用——活记录视角，软删不可见）。**列表管理轮零新增**，AI 段下一
  可用仍 5005。
- **AI 域出参类型口径（与 Java 域不同，前端消费注意）**：
  - 字段命名 snake_case（file_name / create_time / file_split_type）；
  - `id` / `total` 为 JSON **number**（Python 侧不做 Long→String；自增 id 值域内安全）；
  - 时间字段统一字符串 `yyyy-MM-dd HH:mm:ss`；
  - 分页容器 `AiPageResult<T> = { total: number, rows: T[] }`——**不复用** Java 域 `PageResult<T>`
    （其 total 为 string）；
  - 分页查询参数名 `page` / `size`（**非** Java 域的 pageNum/pageSize）。

## 2. POST /rag/kb 创建知识库（perms `ai:kb:add`）

- 入参 `CreateKBReq`：`name` string 1..50 必填（知识库名称，唯一）；`description` string ≤500 **必填**
  （描述信息；用户 WIP 契约形态，DDL 列可空、必填由入参层表达）。
- 返回 `R<int>`：`data` = 新知识库 id。
- 分支：200 成功 / 403 无 perms / 1001 name 空·超长、description 缺失·超长 / 5003 活记录重名或墓碑占键。
- 审计：create_by = 网关注入 X-User-Account（require_perms 依赖 set contextvar）。

## 3. POST /rag/kb/upload 上传文件（perms `ai:kb:add`，2026-10-15 补录）

- 方法/路径：POST /rag/kb/upload；`kb_id` 为 **query 参数**（int 必填）；Content-Type
  multipart/form-data，文件字段名 `file`（单文件，必填）。
- 返回 `R<int>`：`data` = **kb_id**（非文件 id）。
- 分支：
  - 200 上传成功；
  - 403 无 `ai:kb:add`；
  - 1001 kb_id 缺失或非整数、file 缺失；
  - 5004 知识库不存在（活记录视角，软删不可见）；
  - 500 系统异常——**仅支持 PDF / DOCX**，其他类型（.txt/.md 等）解析失败走此分支；Milvus 或 embedding
    后端（Ollama）不可达亦走此分支（事务整体回滚，MySQL 无残留）。
- 行为要点（前端对接须知）：
  - 同一文件可重复上传：file_path 落随机 uuid，每次生成新登记行（不查重、不冲突）；
  - 入库副作用：文件登记行（分片参数快照 child 128/overlap 20/parent 500、split_type
    `"parent-child"`、file_chunk_count=子块数）+ 父子分块行 + Milvus 子块向量；
  - 文件大小上限未显式定义（实现时验证网关/部署层限制）；
  - 前端建议 accept=".pdf,.docx" 双防线 + 请求超时 ≥120s（分片与向量写入为长操作）。
- 审计：create_by = X-User-Account。

## 4. GET /rag/kb/list 知识库分页列表（perms `ai:kb:list`；2026-10-15 列表管理轮重写）

- 入参（query）：`page` int 默认 1、`size` int 默认 10、`name` string 可选默认不传。
  - 越界钳制不报错（page<1 取 1；size 取 1..200 上限，对齐 Java 分页插件 maxLimit 口径）；
  - page / size 非整数 → 1001；name 长度 >50 → 1001；
  - `name` 匹配语义：**包含匹配**（`LIKE '%name%'`）；不传或空串 = 不过滤全量分页。
- 语义：分页查活知识库（软删不可见），**id 倒序**（新建库居首——列表管理轮行为变更，旧版为 id 升序
  全量）。
- 返回 `R<AiPageResult<KbVo>>`。KbVo 字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | number | 知识库 id |
| name | string | 知识库名称 |
| description | string \| null | 描述信息 |
| create_time | string | 创建时间 `yyyy-MM-dd HH:mm:ss`（列表管理轮 additive 补列，管理页时间列） |

- 示例：`{"code": 200, "msg": "操作成功", "data": {"total": 2, "rows": [{"id": 2, "name": "e2e_x", "description": "d", "create_time": "2026-10-15 09:00:00"}, {"id": 1, "name": "test", "description": "test", "create_time": "2026-10-14 18:00:00"}]}}`
- 分支：200 / 403 / 1001（非整数参数、name 超长）。
- 说明：库级 file_count / file_chunk_count 恒 0 不入出参（用户拍板：不显示文档数/分块数）。

## 5. PUT /rag/kb/{kb_id} 编辑知识库（perms `ai:kb:update`，2026-10-15 列表管理轮新增）

- 路径参数：kb_id int 必填（非整数 → 1001）。HTTP 方法/路径形态对齐 Java 域用户域先例（修改 PUT、
  返回 data=null）。
- 入参 `UpdateKBReq`（body JSON）：`name` string 1..50 必填；`description` string ≤500 **必填**（与
  创建 §2 同口径，双必填）。
- 返回 `R<null>`：`data` 恒 null。
- 分支：
  - 200 编辑成功；
  - 403 无 `ai:kb:update`（持 `ai:kb:add` 亦拒——权限按动作分立）；
  - 1001 kb_id 非整数、name 空·超长、description 缺失·超长；
  - 5004 知识库不存在（活记录视角）；
  - 5003 改名为他库现有名（**保持自身当前名放行**——非重命名不触发）。
- 行为要点：name + description 全量覆盖语义（两字段均必填，无部分更新通道）；并发重名由 uk_name
  兜底同转 5003。
- 审计：update_by = X-User-Account + update_time。

## 6. DELETE /rag/kb/{kb_id} 删除知识库（perms `ai:kb:delete`，2026-10-15 列表管理轮新增）

- 路径参数：kb_id int 必填（非整数 → 1001）。
- 入参：无 body。
- 返回 `R<null>`：`data` 恒 null。
- 分支：
  - 200 删除成功；
  - 403 无 `ai:kb:delete`；
  - 1001 kb_id 非整数；
  - 5004 知识库不存在（含二次删除——软删后不可见即 5004）。
- 行为要点（前端对接须知）：
  - **三表级联软删**（同一事务）：ai_kb 行 + 其下全部 ai_kb_file 行 + 全部 ai_kb_chunk 行置 deleted=1，
    无「库下有文件阻止删除」前置约束——直接级联；
  - **物理向量不动**（Milvus 向量按 chunk pk 存于共用 collection）：已删库的向量成孤儿，检索轮做
    collection 库级隔离时统一清理（`docs/handoff/ai.md` 在档）；检索链路当前未上线，无用户可见影响；
  - 删除后该 kb_id 的 files 查询（§7）即返 5004；
  - 前端删除前自行 `ElMessageBox.confirm` 确认（契约不提供 dry-run/预检端点）。
- 审计：三表 update_by = X-User-Account + update_time。

## 7. GET /rag/kb/{kb_id}/files 知识库文件分页（perms `ai:kb:list`，2026-10-15 新增；列表管理轮节号顺延）

- 路径参数：kb_id int 必填；query：page int 默认 1、size int 默认 10。
  - 越界钳制不报错（page<1 取 1；size 取 1..200 上限，对齐 Java 分页插件 maxLimit 口径）；
  - kb_id / page / size 非整数 → 1001。
- 语义：先校验知识库存在（活记录），不存在 → 5004；再分页查文件（id 倒序，软删不可见）。
- 返回 `R<AiPageResult<KbFileVo>>`。KbFileVo 字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | number | 文件 id |
| file_name | string | 文件名 |
| file_split_type | string | 分片类型：`"parent-child"`（父子分片）；预留 `"recursion"`（递归分片） |
| create_time | string | 上传时间，`yyyy-MM-dd HH:mm:ss` |

- 示例：
  `{"code": 200, "msg": "操作成功", "data": {"total": 2, "rows": [{"id": 3, "file_name": "guide.pdf", "file_split_type": "parent-child", "create_time": "2026-10-15 09:30:00"}]}}`
- 分支：200 / 403 / 1001（非整数参数）/ 5004 知识库不存在。
- 说明：文件级分块数（DB 列为上传链路写入的真实数据）本轮亦不展示（拍板「不显示分块数」从严解读，
  后续 additive 可补）。
